# 用語集

この講座に出てくる用語を、分野ごとにまとめました。各章を読んでいて意味を忘れたときに戻ってきてください。「章」の列は、その用語を詳しく説明している章です。

英語の呼び名がある用語は、本文と同じく「日本語（英語の呼び名）」の形で載せています。製品の公式ドキュメントは英語の呼び名で書かれているので、両方を覚えておくと読みやすくなります。

## 非同期処理の考え方

| 用語 | 意味 | 章 |
| :--- | :--- | :--- |
| 同期呼び出し | 相手を呼び出し、処理が終わるのを待ってから次へ進むやり方 | [1](./01-sync-call-limits.md) |
| 非同期処理 | 時間のかかる処理や後でよい処理を、ユーザーの待ち時間の外側で進めるやり方 | [0](./00-overview.md) |
| 障害の連鎖 | 呼び出し先の1つが落ちたことで、呼び出し元まで失敗すること | [1](./01-sync-call-limits.md) |
| 密結合 | 呼び出し元が呼び出し先を直接知っていて、片方の変更がもう片方に響く状態 | [1](./01-sync-call-limits.md) |
| 疎結合 | 送る側と受け取る側がお互いを直接知らず、独立して変更できる状態 | [15](./15-what-is-pubsub.md) |
| 結果整合性 | 処理の直後はまだ反映されていないが、少し遅れて全体がそろう状態 | [4](./04-design-thinking.md) |
| スタック（LIFO） | 最後に入れたものから取り出す入れ物。後入れ先出し | [2](./02-async-alternatives.md) |
| キュー（FIFO） | 最初に入れたものから取り出す入れ物。先入れ先出し。メッセージングでは、メッセージを預かる場所を指す | [2](./02-async-alternatives.md) |
| ポーリング | 何か届いていないかを、一定間隔で確認しに行くやり方 | [7](./07-http-api.md) |

## 非同期処理の5つのパターン

| 用語 | 意味 | 章 |
| :--- | :--- | :--- |
| ジョブ | 「やること」1件分。領収書 PDF を1つ作る、など | [3](./03-async-map.md) |
| ワーカー | キューからジョブを取り出して処理する働き手 | [2](./02-async-alternatives.md) |
| ジョブキュー | ジョブをキューに積み、ワーカーに処理させる仕組み。非同期処理の土台 | [10](./10-job-queue.md) |
| 定期バッチ | 決まった時刻や間隔で、自動で動く処理 | [14](./14-batch.md) |
| Pub/Sub（パブサブ） | 1つの知らせを、受け取りたい相手全員に配る仕組み。Publish/Subscribe の略 | [15](./15-what-is-pubsub.md) |
| ワークフロー | 1つのジョブが終わると次のジョブが積まれる、ジョブの連鎖 | [20](./20-workflow-chain.md) |
| イベントログ | 起きたことを消さずに記録し、あとから何度でも読み直せる仕組み | [5](./05-messaging-products.md) |

## メッセージのやり取りの登場人物

| 用語 | 意味 | 章 |
| :--- | :--- | :--- |
| メッセージ | やり取りするデータの1件分。本文と、付加情報（プロパティ）でできている | [15](./15-what-is-pubsub.md) |
| 送り手（パブリッシャー） | メッセージを送る側。プロデューサー（Producer）とも呼ぶ | [5](./05-messaging-products.md) |
| 受け手（コンシューマー） | メッセージを受け取って処理する側。Pub/Sub ではサブスクライバー（Subscriber）とも呼ぶ | [5](./05-messaging-products.md) |
| ブローカー（メッセージブローカー） | 送り手と受け手の間に立ち、メッセージを預かって届ける仲介役のソフトウェア。RabbitMQ がその1つ | [2](./02-async-alternatives.md) |
| プロトコル | プログラム同士がやり取りするときの約束事（通信のルール）。HTTP や AMQP など | [5](./05-messaging-products.md) |
| キュー型 | 受け手が処理を終えると、メッセージが消える系統の製品。RabbitMQ、Amazon SQS など | [5](./05-messaging-products.md) |
| ログ型 | 読んでもメッセージが消えず、保持期間内なら読み直せる系統の製品。Kafka など | [5](./05-messaging-products.md) |
| オフセット | ログ型で、受け手が「何番目まで読んだか」を表す位置 | [5](./05-messaging-products.md) |
| マネージドサービス | サーバーの運用をクラウド側に任せられるサービス | [5](./05-messaging-products.md) |

## RabbitMQ（AMQP）の部品

| 用語 | 意味 | 章 |
| :--- | :--- | :--- |
| AMQP | RabbitMQ が使うメッセージングのプロトコル。この講座では AMQP 0-9-1 を使う | [6](./06-amqp.md) |
| 接続（Connection） | プログラムとブローカーの間の通信路。作るのに時間がかかるので使い回す | [6](./06-amqp.md) |
| チャネル（Channel） | 1本の接続の中に作る、軽い通り道。スレッドごとに分ける | [6](./06-amqp.md) |
| エクスチェンジ（Exchange） | メッセージを受け取り、どのキューに届けるかを決める振り分け役。メッセージは保存しない | [6](./06-amqp.md) |
| バインディング（Binding） | 「このエクスチェンジに来た、この条件のメッセージを、このキューへ」という規則 | [6](./06-amqp.md) |
| ルーティングキー | メッセージに付ける宛先ラベル。バインディングの条件と照らし合わされる | [6](./06-amqp.md) |
| バインディングキー | バインディングに付ける条件。topic では `*` や `#` のワイルドカードを使える | [17](./17-topic.md) |
| 既定エクスチェンジ | 名前が空文字のエクスチェンジ。キュー名をルーティングキーにすると、そのキューに届く | [6](./06-amqp.md) |
| direct / fanout / topic / headers | エクスチェンジの4つの種類。完全一致・全部へ・パターン一致・ヘッダーの値で振り分ける | [6](./06-amqp.md) |
| プロパティ | メッセージに付ける付加情報（メタデータ）。`messageId`・`type` など | [6](./06-amqp.md) |
| 仮想ホスト（Virtual host） | 1つの RabbitMQ の中を、名前の区画に分ける仕組み | [6](./06-amqp.md) |

## メッセージの受け取り方

| 用語 | 意味 | 章 |
| :--- | :--- | :--- |
| プッシュ型 | ブローカーのほうから、届いたメッセージを受け手に届けてくれる受け取り方 | [9](./09-point-to-point.md) |
| プル型 | 受け手のほうから、メッセージを取りに行く受け取り方 | [7](./07-http-api.md) |
| 購読（subscribe） | 「このキューやトピックのメッセージを受け取ります」と登録すること | [9](./09-point-to-point.md) |
| P2P（ポイント・ツー・ポイント） | 1件のメッセージを、受け手のうち1人だけに渡す形 | [9](./09-point-to-point.md) |
| ラウンドロビン | 複数の受け手に、順番に1件ずつ配るやり方 | [9](./09-point-to-point.md) |
| ack（アック） | 受け手からブローカーへの「処理が終わりました」という通知 | [3](./03-async-map.md) |
| 自動 ack / 手動 ack | 届けた時点で処理済みとみなすか、受け手が処理後に自分で ack を返すか | [11](./11-not-losing-messages.md) |
| prefetch | ack をまだ返していないメッセージを、手元に最大何件まで受け取るかの上限 | [10](./10-job-queue.md) |
| 一時的な購読 | 起動している間だけ受け取る購読。止めるとキューごと消える | [16](./16-fanout.md) |

## トラブルと対策

| 用語 | 意味 | 章 |
| :--- | :--- | :--- |
| 永続化（durable / persistent） | 再起動しても消えないよう、ディスクにも書いておくこと。キューとメッセージで別々に指定する | [11](./11-not-losing-messages.md) |
| 再配達 | ack されなかったメッセージを、ブローカーがもう一度届けること | [11](./11-not-losing-messages.md) |
| パブリッシャー確認（publisher confirms） | 送り手が、ブローカーがメッセージを受け取ったことを確かめる仕組み | [11](./11-not-losing-messages.md) |
| at-most-once / at-least-once / exactly-once | 配達の保証の水準。最大1回（消えうる）・最低1回（重複しうる）・ちょうど1回 | [11](./11-not-losing-messages.md) |
| クォーラムキュー | 複数台のサーバーに複製して保存する、RabbitMQ のキューの種類 | [11](./11-not-losing-messages.md) |
| 冪等（べきとう） | 同じ操作を何回行っても、1回行ったときと結果が変わらない性質 | [12](./12-idempotency.md) |
| 毒メッセージ | 何度処理しても必ず失敗するメッセージ | [13](./13-dead-letter-queue.md) |
| デッドレターキュー（DLQ） | 処理できなかったメッセージを別に取っておく専用のキュー | [13](./13-dead-letter-queue.md) |
| DLX | 拒否されたメッセージの転送先になるエクスチェンジ。Dead Letter Exchange の略 | [13](./13-dead-letter-queue.md) |
| ヘッドオブラインブロッキング | 先頭の1件が詰まり、後ろのメッセージも進めなくなる現象 | [13](./13-dead-letter-queue.md) |
| 指数バックオフ | 1秒、2秒、4秒と、失敗のたびに間隔を広げながらやり直す方法 | [13](./13-dead-letter-queue.md) |
| スケジューラー | 時刻になったらジョブを積む役のプログラム | [14](./14-batch.md) |

## Pub/Sub とメッセージの設計

| 用語 | 意味 | 章 |
| :--- | :--- | :--- |
| トピック | Pub/Sub で、送り手がメッセージを発行する宛先 | [15](./15-what-is-pubsub.md) |
| サブスクリプション | 受け手ごとの受け口。RabbitMQ では、エクスチェンジにバインドしたキューにあたる | [15](./15-what-is-pubsub.md) |
| イベント | 起きた事実の通知。名前は過去形（注文が確定した） | [15](./15-what-is-pubsub.md) |
| コマンド | 誰かへの依頼。名前は命令形（メールを送れ） | [15](./15-what-is-pubsub.md) |
| 空間・時間・同期の切り離し | Pub/Sub が送り手と受け手を切り離す3つの意味 | [15](./15-what-is-pubsub.md) |
| イベントバス | 出来事を配る共通の通り道。プログラム内の部品、クラウドのサービス、設計上の役割と、文脈で指すものが変わる | [15](./15-what-is-pubsub.md) |
| スキーマ | メッセージの本文に入れる項目の構成 | [18](./18-message-design.md) |
| 寛容な読み手（Tolerant Reader） | 知らない項目を無視し、必要な項目だけを読む受け手の作り方 | [18](./18-message-design.md) |
| 通知型 / 状態転送型 | イベントの本文に ID だけを入れるか、内容をすべて入れるかの2つの考え方 | [18](./18-message-design.md) |
| パーティション | 同じキー（注文IDなど）のメッセージを同じ場所に集めるための分割 | [19](./19-ordering.md) |

## ワークフローと、この先で学ぶテーマ

この講座では、次の用語は名前の紹介だけにとどめています。どれも、それだけで1つの講座になる大きなテーマです。

| 用語 | 意味 | 章 |
| :--- | :--- | :--- |

| オーケストレーション | 指揮者（オーケストレーター）が流れを管理し、各手順に命令を出す組み立て方 | [20](./20-workflow-chain.md) |
| 二重書き込み問題 | DB の更新とメッセージの送信の、片方だけが成功してしまう問題 | [21](./21-wrap-up.md) |
| Outbox パターン | 送るべきメッセージを DB に一緒に保存し、別のプログラムが送り出す方法 | [21](./21-wrap-up.md) |
